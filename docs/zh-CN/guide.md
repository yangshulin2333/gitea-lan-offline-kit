# 局域网 Git 部署与团队操作手册

本手册配套包内固定版本，所有步骤可离线阅读。先用练习仓库验收，再导入正式项目。离线指无需互联网，服务器与成员之间仍需局域网。

## 1. 包内内容与适用范围

|内容|作用|
|---|---|
|服务端/gitea.exe|Gitea 1.27.3 x64；网页、账号、仓库服务|
|成员客户端/安装程序|Git 2.53.0.2、TortoiseGit 2.19.1.0、简体中文语言包2.19.0.0|
|工具/01-部署新服务器.ps1|新建目录、生成无密码配置、注册Windows服务和异常重启|
|工具/02-开放局域网.ps1|初始化完成后开放本地子网访问|
|工具/03-完整备份.ps1|停止本包部署的服务，复制并逐文件校验，再恢复服务|
|验收记录.txt|已验证、未验证及跳过项目|

仅适用于Intel/AMD x64 Windows。当前实测系统是Windows 11；Windows 10和全新电脑安装未实测。不要用在32位、ARM、网络共享盘或已有Gitea实例上。优先内置健康NTFS磁盘，路径用简单英文，例如D:\Gitea。没有D盘可用C:\Gitea。服务器不依赖TortoiseGit，管理员要做客户端练习时才安装它。

包内不含现有用户和仓库。新装需要重新建账号、组织、权限。迁移旧数据属于恢复操作，见第9节，不能用新建脚本覆盖旧实例。

## 2. 部署前填写的信息

- 服务器安装目录：________。
- 备份目录和物理磁盘：________。
- 服务器局域网IPv4：________；端口固定3000。
- 管理员账号：________；管理员邮箱：________。
- 密码由管理员本人设置并另行保管，不写进共享手册。
- 审核负责人：________、________。

推荐路由器DHCP地址保留；不会配置时请网络负责人处理。未经网络规划不要随便填写静态IP。地址变化会影响网页、克隆地址和凭据。本次原环境192.168.10.10只是示例，换电脑必须使用新电脑真实地址。

电源：接电时关闭自动睡眠和休眠；保持磁盘接入、盘符不变。不要关闭整个防火墙。VPN需允许局域网直连，本包不会修改VPN或电源策略。

## 3. 新服务器安装

### 3.1 解压和安装Git

将整个包复制到新电脑，全部解压；不要在ZIP里运行工具。先运行Git安装程序，保留Git LFS和Git Credential Manager，PATH选择“Git from the command line and also from 3rd-party software”。使用默认程序目录C:\Program Files\Git。Next=下一步，Install=安装，Finish=完成。

安装后重新打开PowerShell，运行 `git --version` 和 `git lfs version`，都应显示版本。

### 3.2 运行部署脚本

开始菜单搜索“Windows PowerShell”，右键“以管理员身份运行”。用cd进入离线包的工具目录，例如：

```powershell
cd 'D:\packages\局域网Git离线部署包\工具'
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\01-部署新服务器.ps1'
```

路径按实际解压位置修改。Bypass只对这个进程生效；若组织策略禁止脚本，联系管理人员，不规避组织策略。输入全新服务器目录和本机局域网IP。脚本遇到已有服务、已有目录或端口占用会停止。遇到失败不要删除已有数据重试；先保留报错检查服务与目录状态。

脚本不会写入任何固定密码。配置和数据目录仅授权本机管理员、SYSTEM和LocalService。服务以LocalService运行、延迟自动启动，异常退出后60秒、60秒、120秒重试启动。磁盘尚未挂载、损坏或端口长期占用仍可能导致启动失败。

### 3.3 在本机网页创建管理员

打开 `http://127.0.0.1:3000/`。等待服务首次启动后进入安装页；若页面英文，在页面语言选择简体中文。

- 数据库：SQLite3，不需要另装MySQL。
- 数据库文件：所选安装目录\data\gitea.db。
- 仓库根目录：所选安装目录\repositories。
- LFS目录：所选安装目录\data\lfs。
- 运行用户名：LOCAL SERVICE。
- 域名：刚输入的局域网IP；HTTP端口3000。
- 基础URL：http://你的局域网IP:3000/，保留末尾斜杠。
- 禁用SSH，不配置邮件，关闭开放注册。
- 展开管理员账号设置，创建自己的管理员、邮箱和强密码，不要留空。

核对后安装。此阶段只监听127.0.0.1，其他电脑不能进入初始化页。安装完成跳转到局域网地址而打不开是因为尚未开放，执行下一步。

### 3.4 开放局域网

同一管理员终端运行：

```powershell
powershell.exe -NoProfile -ExecutionPolicy Bypass -File '.\02-开放局域网.ps1'
```

输入刚才服务器目录。脚本检查安装锁已启用、服务路径匹配、本机拥有该IP，随后绑定该局域网IP并开放TCP3000，仅允许LocalSubnet。分别在本机和同事电脑打开局域网地址，使用各自账号登录。服务初始化后只在选定IP监听，不必再使用127.0.0.1。

### 3.5 重启验收

先保存其他工作，重启服务器。不要手工启动Gitea，让同事访问网页并克隆练习仓库；建议在Windows尚未登录时检查一次。服务延迟启动可能需要等待一两分钟。记录实际结果，不以“自动”设置代替实测。

## 4. 账号、组织和仓库

管理员头像菜单→管理后台→身份及认证→账户管理，创建独立成员账号，按需要求首次登录改密码。不要共享管理员账号；邮箱用于提交作者关联，不是密码。

建立私有组织，例如team；建立私有练习仓库git-practice并初始化README。组织→团队→新团队：指定仓库；代码、工单、合并请求可写，其他按需可读。添加成员后，还必须在团队的仓库页添加git-practice，否则成员没有仓库访问权限。

管理员和另一名负责人可以承担互相审核。一般成员不授予站点管理员身份。

## 5. 成员安装与首次克隆

按顺序安装Git、TortoiseGit、中文语言包。右键→显示更多选项→TortoiseGit→Settings→General→Language→中文（简体）→Apply。主程序2.19.1.0与包内2.19.0.0语言包是当前实测组合；不要给其他版本随意安装这份语言包。

TortoiseGit→设置→Git：名称填写自己的姓名或账号，Email填写自己账号的邮箱。这个设置是提交署名，不是登录认证。新终端运行 `git lfs install` 启用当前用户的LFS支持。

网页打开仓库→代码→复制HTTP克隆地址。在本地项目父文件夹右键→TortoiseGit→克隆；选择新的项目子目录。保持非裸仓库、正常检出，不选深度限制；HTTP无需加载Putty密钥。登录自己的Gitea账号。Authentication successful表示成功。

不同电脑的本地项目目录可以不同。不要克隆进服务器repositories目录，不要编辑.git文件夹。

## 6. 日常分支开发与审核

1. 当前工作应已提交或妥善保存；切换/检出main，然后拉取origin/main。
2. 创建新任务分支，例如member02-map，并切换到新分支。每个任务新建分支，不长期重复使用已合并任务分支。
3. 修改文件；提交前检查差异，只勾选本次任务文件，填写清楚的中文说明。
4. 推送：本地member02-map、远端member02-map、远端名称origin。不要填main，不使用强制推送。
5. 网页→合并请求→创建：左侧“合并到”main；右侧“拉取从”任务分支。main对main没有差异。
6. 确认差异后填写标题、说明，创建请求。
7. 另一位审核人打开“文件变动”，逐项检查，勾已查看，点评审。通过=批准；评论不等于批准；请求变更=需要修改。
8. 审核通过后，由有权限的人点击“创建合并提交”，检查确认页，再次确认；“已合并”才算完成。
9. 双方切回main，再拉取。网页合并不会自动更新本地文件。

未完成本地修改时不要强行切分支。提交只保存到本地，推送才上传服务器。已合并分支可稍后删除，但先确认合并成功且没有额外未合并工作；本次入门可保留。

### 主分支保护

仓库→设置→分支→添加新规则，名称main。文件表达式留空；禁用推送、禁用强制推送；不要求尚未配置的签名。批准数1，只计指定负责人名单；取消过时批准。合并白名单仅负责人；不允许绕过；拒绝审核或官方审核未结束时阻止合并；管理员也遵守。未配置CI时不启用状态检查。选择白名单时必须点选搜索结果。

保存规则不等于验证规则。建议用练习提交验证直接推送被拒、未批准不能合并、批准后能合并。当前原环境按用户要求跳过拦截验证。撤销已推送提交以后也需在任务分支上完成并走合并请求。

## 7. 版本撤销

### 尚未提交

选中文件→TortoiseGit→还原，核对文件后执行。丢弃的未提交内容通常不能用Git找回；重要内容先复制到仓库外保存。

### 已提交并推送

保护启用后先从最新main创建撤销任务分支。显示日志→选中确实要撤销的普通提交→右键“还原此版本做出的变更”。检查文件，再提交一次撤销记录，推送任务分支并发起合并请求。原提交历史保留。

不要误选“重置main到此版本”。撤销合并提交、多条相互依赖的提交比较复杂，先在练习分支确认结果；本次只实测普通单条提交撤销。

## 8. 多人改同一文件和冲突

不同位置可能自动合并，同一行可能冲突。不要把认证失败当成冲突。真正冲突日志包含CONFLICT和Merge conflict。

先与同事商量最终内容，再处理文件。TortoiseGit菜单随右键对象和Win11菜单层级不同：在具体文件上右键→显示更多选项→TortoiseGit，可见“编辑冲突”“解决冲突”。

使用编辑器时，上方左右是双方版本，下方“已合并”是最终文件。整理下方内容，去掉冲突标记，保存，再点绿色“标记为已解决”。若通过普通文本编辑器完成，再进入“解决冲突”文件列表，勾文件、确定。最终必须提交一次合并结果，再推送。标记已解决不会替你判断内容是否正确。

练习示例最终内容：

```text
项目名称：团队练习
本周任务：制作大厅地图
本周任务：制作战斗地图
```

保护启用后，在开发分支中合入main来解决冲突，不直接推送main。不要把示例中“双方改动都保留”当作通用规则：代码可能必须择一或重写，并运行相关测试。

图片、模型和其他二进制资源通常无法逐行合并，应约定负责人、避免同时修改；LFS用于大文件存储，并不会自动解决资源冲突。正式游戏项目的LFS规则和忽略文件仍需按实际文件类型制定。

## 9. 备份、恢复与迁移

备份包含数据库、仓库、LFS、附件、配置和密钥。单独克隆仓库不能备份账号、权限或全部LFS对象。使用另一块物理磁盘保存副本，备份含敏感信息，不发给成员。

本包新部署实例可运行03-完整备份.ps1，输入安装目录、备份目录、确认BACKUP。请事先通知团队暂停操作；脚本短暂停服，复制整个实例并校验SHA256，再恢复服务。不打ZIP以避免大项目压缩大小限制。服务或配置不属于本工具时会停止。

本工具仅覆盖安装目录内数据。若管理员后来把数据库、仓库、LFS或附件路径移到外部，必须将这些外部路径纳入新的备份方案，不能继续依赖本脚本。复制成功不代表恢复验收通过。

恢复时先保留故障现场和原备份，使用独立副本，关闭现有服务后再操作。最容易复现的迁移方式是在新电脑保留相同安装路径和相同Git版本：复制“服务器文件”到原安装路径，恢复LocalService权限、HOME及服务配置。不要再进行网页初始化。账号密码仍是备份时的密码。

若迁移盘符或IP，必须检查app.ini中数据库、仓库、LFS、附件、日志等全部路径和ROOT_URL/DOMAIN/HTTP_ADDR，并重新生成仓库钩子；旧钩子可能指向旧程序路径。新建部署脚本不承担旧数据迁移，禁止拿它覆盖备份。跨机恢复尚未实测，本包不把这一流程称为一键迁移。需要先在隔离新机验收账号、权限、历史、Git上传下载和LFS下载，再切换成员地址。

遗失管理员密码时，由服务器管理员使用对应版本Gitea管理命令重置，避免把密码粘贴进共享聊天或日志。离线运行gitea.exe admin user change-password --help查看本版本参数；恢复管理员登录后再开放成员。不要删除数据库或关闭认证。

## 10. 故障排查

|现象|先做什么|
|---|---|
|网页打不开|确认服务器开机、IP没变、Gitea服务运行；等待延迟启动。检查选定IP与TCP3000，不关闭整个防火墙|
|服务起不来|运行services.msc查看Gitea；查安装目录log；检查磁盘、Git路径、权限和端口占用|
|Authentication failed|原样重试一次；当前两台电脑出现过首次失败后重试成功，原因未彻底确认|
|持续认证失败|确认账号可网页登录、账号未禁用、仓库权限正确；只检查该站点凭据，不能清空所有Windows凭据|
|受保护分支拒绝推送|保留本地提交，创建并切到任务分支后推送，通过合并请求；不要强制推送|
|non-fast-forward|远端有新提交；先获取并合并到正确开发分支，处理冲突再推送|
|右键菜单没有相关选项|选中实际文件，点击显示更多选项；核对是否在仓库内|
|LFS下载失败|确认git lfs已安装、服务器LFS开启、对象随备份保留、网络和权限正常|
|无法合并|检查批准人数、审核人名单、是否有请求变更、未完成评审或冲突|

提交签名提示不是登录密码错误。未配置签名时不要要求签名提交。HTTP仅用于受控局域网，当前没有部署HTTPS，不要将3000直接映射到公网。

## 11. 新电脑验收清单

- 断开互联网但保留局域网，全部安装程序能安装，页面与手册能使用。
- 新管理员登录、成员独立登录、私有仓库权限正确。
- 真正重启后，不手工启动服务即可访问；最好未登录Windows时也能访问。
- 正常分支提交、推送、审核、合并、双方拉取通过。
- 保护拒绝直接推送和未审核合并。
- 普通提交撤销和文本冲突处理通过。
- LFS上传后另一台电脑全新克隆下载，文件大小与哈希一致。
- 备份在独立电脑恢复，账号、历史、权限、Git传输及LFS均通过。
- 至少经过令牌到期后的首次操作观察，记录认证问题。

以上仍未完成的项如实保留，不能把当前测试结果推广成所有系统兼容保证。

## 12. 英语学习

- Clone：克隆。Clone the repository. 克隆这个仓库。
- Commit：提交。Commit your changes. 提交你的修改。
- Push：推送。Push your branch. 推送你的分支。
- Pull：拉取。Pull the latest changes. 拉取最新修改。
- Review：评审。Please review this change. 请审核这项修改。
- Conflict：冲突。Resolve the conflict first. 先解决冲突。
- Backup：备份。Keep a backup. 保留一份备份。
- Restore：恢复。Restore from a backup. 从备份恢复。
